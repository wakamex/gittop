gittop is a terminal monitor for your latest Git activity across every repository under a folder, including local-only repositories with no remote. It lists the repositories with commits in a time window, newest first, and updates within a fraction of a second of each new commit, merge, rebase, or pull. It reads only your local repositories and never contacts a remote.

Install it with `cargo install --locked gittop`. It needs `git` on the PATH and Rust 1.88 or newer, and has been tested on Linux.

## What it does

- Lists each repository's age since its newest commit, checked-out branch, commits in the window, unpushed commits (or `local` when it has no remote), and latest commit subject.
- Shows a feed of the commits themselves across all repositories, listing a commit shared by several clones once with every repository that has it.
- Counts only your own commits with `m`, matching each repository's `user.name` and `user.email` or values passed with `--me`.
- Filters by repository, branch, author, or commit subject, and widens or narrows the window from 1 hour to 30 days.
- Lists a repository once instead of once per linked worktree; `--worktrees` lists each worktree as its own row.
- Prints the current activity once with `--once`, as text or JSON, for scripts.

## Resource use

gittop watches the folders holding each repository's branch logs, `HEAD`, and `packed-refs` for changes, and runs `git` only in a repository whose branches changed. Index rewrites by `git status` do not trigger it. On a machine with 921 repositories, the live view watches about 2,800 folders, picks up a commit about 0.1 seconds after it is made, and uses about 0.3% of one CPU core while idle. A 24-hour `--once` run takes about 0.2 seconds with the repository list cached.

## Known limits

- Uncommitted changes are not shown, because measuring them needs `git status` in every repository.
- Commits that arrive only through `git fetch` appear once they are merged or pulled into a local branch.
- A repository nested inside an existing one appears with the next daily rebuild of the repository list, or with `--rescan`.
