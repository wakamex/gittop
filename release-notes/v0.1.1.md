gittop now follows repositories as they come and go, and starts faster.

- The live view adds a repository created under the root while it runs, such as a new clone, `git init`, or a repository nested a few folders down, and drops one that is deleted, within about 0.4 seconds. Repositories created while gittop was not running appear right after it starts, instead of after the daily rebuild of the repository list. A new linked worktree stays hidden behind its repository unless `--worktrees` is given. ([`b52f61f`](https://github.com/wakamex/gittop/commit/b52f61fbc58e48488ef9eacd7609a357fd42c0e2))
- The live view shows a full screen in about 0.2 seconds, even right after a project folder was added, because it starts from the cached repository list and brings it up to date in the background. ([`b52f61f`](https://github.com/wakamex/gittop/commit/b52f61fbc58e48488ef9eacd7609a357fd42c0e2))
- Rebuilding the repository list, which `--once` still does after a root folder changes, takes about 0.7 seconds for 1,020 repositories instead of 2.4 to 10, because finding repositories no longer runs `git` in each one. ([`6770501`](https://github.com/wakamex/gittop/commit/677050136673b9a554e1159f50e7512cce6a9a75))
- An empty `.git` folder inside another repository no longer shows up as a second copy of that repository. ([`6770501`](https://github.com/wakamex/gittop/commit/677050136673b9a554e1159f50e7512cce6a9a75))

Watching for new repositories uses one inotify watch per searched folder, about 36,000 under a folder with 921 repositories, out of the per-user limit in `fs.inotify.max_user_watches`. Idle CPU use stays at about 0.3% of one core.

## Changes

- Find repositories without running git, so a cache rebuild takes 0.7 seconds ([`6770501`](https://github.com/wakamex/gittop/commit/677050136673b9a554e1159f50e7512cce6a9a75))
- Add and drop repositories created or removed while the live view runs ([`b52f61f`](https://github.com/wakamex/gittop/commit/b52f61fbc58e48488ef9eacd7609a357fd42c0e2))
